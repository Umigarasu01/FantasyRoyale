# Prototype Milestones

## 方針

プロトタイプ完成までのマイルストーンを大きめに分ける。
詳細なクラス構成や仕様は、各マイルストーン開始前に相談して決める。

従来のMilestone 1では旧96x72森林Reference Map、移動・地形判定・Camera追従、自由配置EventSocket、回復の泉を通す共通Event Runtime、6候補から3地点を選ぶ再現可能なEvent Pool抽選まで一時`PreviewDebug`足場で検証済み。現在のReference Mapは48x32のForestRestartへ置換済みで、素材・Sceneの現在地は[Map Plan](art/map-plan.md)を参照する。Milestone 2はStep 1で純C# Character Health、Step 2で共通Move Command、本番`CharacterActor2D`、人間入力Adapterを実装し、Previewを本番移動経路へ移行した。攻撃、装備、正式Character Prefabは未着手。

## 2026-10-09 の進行方針

育成中の脱落なしで探索・育成・妨害を行い、各自のビルドを完成させた後に最後のバトルへ進む、シティトライアルのような流れを目指す。全体Mapは暫定24×18U（1U=6 Unity単位、144×108 Unity単位）で進め、エリア収縮は当面採用しない。人数・各フェーズの時間・試合全体の時間・妨害のペナルティ・最終バトルの勝敗方式は未確定。従来の約20分は旧バトロワ案の調整目安として保持し、現在の時間仕様とは扱わない。

上記は設計方針であり、前段の既存実装・検証履歴や既存Sceneを変更した記録ではない。詳細は[Prototype方針](prototype-direction.md)と[Map Plan](art/map-plan.md)を参照する。

## マイルストーン案

### Milestone 1: ビジュアル・探索マップ基盤

目的:
- コンセプトアート準拠の見た目で、探索できる固定マップを作る。
- 複数ロケーション、タイル、オブジェクト、当たり判定、カメラ、ランダム配置ポイントを確認する。

主な成果物:
- 草原、森、水辺、雪原、火山などの固定マップ。
- タイル素材とオブジェクト素材。
- 建物、商人候補、草むら、木、岩、池、橋、道、崖など。
- 地形当たり判定。
- ランダム配置ポイントの初期設計。

### Milestone 2: アクション戦闘基盤

目的:
- ゼルダ風のトップダウン戦闘を成立させる。
- 装備によって通常攻撃や特殊アクションが変わる土台を作る。

主な成果物:
- 移動。
- 通常攻撃。
- 魔法または特殊アクション。
- 武器ごとの攻撃範囲。
- 被弾、HP、撃破。
- 攻撃エフェクト。
- 装備によるアクション差し替え。

### Milestone 3: 試合ループ基盤

目的:
- 一試合の開始から終了までの最小ループを作る。

主な成果物:
- 試合開始。
- プレイヤー/CPUスポーン。
- ランダム配置。
- 育成フェーズ（脱落なし）と最終バトルの状態・切替。
- 最終バトルの勝敗判定と、脱落・観戦を含む進行方式の検討（未確定）。
- 育成と最終バトルを通す試合進行。各フェーズと試合全体の時間は未確定で、移動・育成・妨害・遭遇密度を実測して検討する。

### Milestone 4: 簡易CPU対戦

目的:
- 一人用で対戦テストを回せるようにする。

主な成果物:
- 簡易CPU。
- 探索。
- 近接戦闘。
- 逃走。
- アイテム/商人利用の最小判断。

### Milestone 5: 育成から最終バトルへの移行

目的:
- 育成中の脱落なしで各自のビルドを育て、最後のバトルへ進む流れを確認する。

主な成果物:
- 育成フェーズの終了条件（未確定）。
- 最終バトルへの移行。
- 最終バトルの場所・参加条件・勝敗方式の検証（詳細は未確定）。
- Mapを縮小せずに試合進行を成立させる検証。

### Milestone 6: アイテム・商人・装備拡張

目的:
- 試合中に強化され、アクションが変化する体験を確認する。

主な成果物:
- システム確認用の数個のアイテム。
- 武器装備。
- 魔法/特殊アクション装備。
- 商人購入。
- 装備による攻撃範囲や挙動の変化。

### Milestone 7: マルチプレイ準備

目的:
- 最終的にオンラインマルチ必須である前提から、同期に必要な構造を検証する。

主な成果物:
- 入力コマンドの整理。
- 試合状態の同期候補整理。
- CPU/人間/ネットワーク入力の共通化方針。
- 実装開始するか、設計だけ固めるかの判断。

### Milestone 8: プレイテスト調整

目的:
- 育成と最終バトルの流れが成立するように調整する。各フェーズと試合全体の時間は未確定で、実測により検討する。

主な成果物:
- マップ密度調整。
- 育成／最終バトルの時間・遭遇密度調整（値は未確定）。
- CPU強さ調整。
- アイテム出現率調整。
- 戦闘テンポ調整。

## 次に相談する対象

2026-11-05に森マップの構成と画作りの基準を承認した。内容は[Map Plan](art/map-plan.md)を参照する。次はMilestone 2 Step 3として、最初の通常攻撃と装備アクション基盤を相談する。

- 攻撃方向を4方向、8方向、自由照準のどれにするか。
- Attack Commandへ方向、対象、押下 / 保持など何を含めるか。
- Coreの攻撃範囲・Damage結果と、Unity PhysicsのOverlap / Colliderによる命中候補取得をどう分けるか。
- 発生、持続、硬直、移動可否、割込みをどこまで最初の時間モデルへ含めるか。
- 装備DefinitionをScriptableObjectにする場合の通常攻撃 / 特殊アクションSlotと、Runtime装備状態の最小構造。
- 最初の検証武器を近接一種にするか、近接と遠隔を同時に通して差し替えを実証するか。

正式Character素材、Animation構成、CPU / Network入力Adapter、観戦、復活専用処理はStep 3へ自動的に含めない。
