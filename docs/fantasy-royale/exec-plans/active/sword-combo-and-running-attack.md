# 片手剣の三段コンボと走りながらの攻撃

## 目的

片手剣の攻撃を三段コンボにし、走りながら攻撃できるようにする。あわせて、剣の振り方が不自然な問題を直す。

完了条件は次のとおり。

- 攻撃のボタンを続けて押すと、片手剣が三段まで続く。
- どの攻撃でも足を止めずに動ける。
- 振りの絵で腕と剣が一体で動き、手首だけで剣が回らない。
- 攻撃中も下半身が走り続け、盾が動かない。
- 止まって振ると、棒立ちにならず前へ踏み込む。

## 背景と根拠

所有者は、剣の振り方が変だと指摘し、片手剣の三段コンボと走りながらの攻撃を求めた（2026-11-07）。

原因は次のとおりである。

- 攻撃の体の絵は剣なしで描いたので、腕の動きがパンチになっている。
- 持続の間は1コマのままで、腕が止まって剣だけが手首を軸に回っていた。
- 斬撃の表示は16 pixelの粗い帯を攻撃範囲へ引き伸ばしたもので、剣の先と離れて見える。

走りの絵で効いた方法を試した。剣と盾を持った騎士の攻撃を1枚生成すると、腕と剣が一体で動き、脚も走りのまま描けた。

## 対象範囲

- `CharacterActionState`の移動の制限と連撃
- `CharacterActionSpec`と`CharacterActionDefinition`の段のつながり
- 片手剣の3段のAction
- 騎士の剣を持った攻撃の絵、素手の絵と、ツールの測定
- 斬撃の表示

## 対象外

- 革装備の三段の絵（所有者の判断で、騎士の動きが固まってから作る）
- 弓を引く動きの絵
- 武器の数値の最終調整
- 敵の攻撃やノックバック

## 実装計画

1. 走りながら攻撃できるようにする。
2. 三段コンボの仕組みと、3段のActionを入れる。この時点の絵は今の攻撃の絵を共用する。
3. **Decision Gate:** 絵の生成の承認を得る。
4. 上半身と脚の絵を作り、ツールが手の位置と剣の角度を全コマ測る。攻撃中は上下を分けて見せ、手首を軸に回す処理をやめる。
5. 残像を、剣の軌跡に合う形で出す。
6. Testと実画面で確認し、Documentationを更新する。
7. 所有者が触って動きを確かめる。動きが固まってから、二段目と三段目の違いと革装備の絵を作る。

## 判断記録

- 所有者の指摘で、振る向きを左から右へ変えた。今までは剣の側から盾の側へ、本人から見て右から左へ振っていた。絵は描き直さず、ツールが4コマを逆の順に並べる。描いた振り抜きの姿勢は、腕が体の前を横切るので、逆の向きの構えとしてそのまま読める。止まって振るときの踏み込みは、刃の向きに関係なく前へ出るので、脚の順はそのままにした。
- 所有者の確認で走る速さが遅く感じたので、5から6へ上げた。足の運びも毎秒11から13コマへ上げ、1コマに進む距離を保った。その後、走りを6コマへ描き直し、足の運びは毎秒17コマになった（[地面を蹴る走りへの描き直し](bounding-run-cycle.md)）。
- 攻撃中の移動の速さは、まず通常と同じにする。`CharacterActionState.ActingMovementScale`の1か所で調整できる。
- 最初は、全身セットにローブのような形が入ると腰で分けられないと考え、体を上下に分けなかった。
- 攻撃の絵の脚を走りの姿勢で描く案は失敗した。所有者の確認で下半身が動かず変だと分かった。段の中で脚はほぼ止まり、変化は走りの2〜3分の1だった。
- 剣を描いた三段の絵も切り方が変だった。持続のコマの剣は向きによらずほぼ真横で、攻撃方向から正面で約90度、斜め前で最大136度ずれる。
- 腕だけを別の部品にして回す案を試作したが、所有者の判断で採らない。腕だけ動きが分離して不自然なためである。
- 所有者の判断で、上半身と下半身で分ける。下半身は脚だけの絵で走りのコマを続け、上半身は攻撃の絵を兜の位置で重ねる。兜の位置で揃えると、走りの上下の揺れにも上半身がついていく。
- 上半身の絵は、持続のコマの剣を攻撃方向へ向けて描くようPromptで向きごとに指定する。前、横、後ろの試作で、持続のコマの剣は攻撃方向から1度以内に収まり、継ぎ目も見えなかった。
- 3コマの試作は、盾が振り抜きのコマで反対側へ飛んだので不採用とした。所有者の指示で[一般的な装備差分の手法](../../references/sprite-equipment-layering.md)を調べた。
- 手法に合わせて次の決まりにする。1振りは4コマで、シートは走りと同じ3行4列とする。行の中で動くのは利き腕と武器だけで、盾の手は全コマ同じ位置に留める。盾は向きごとに1つの位置へ固定する。残像は速い2コマにだけ出す。
- 盾の白い十字は刃と同じ灰色なので、刃を探す前に盾の範囲を除く。
- 所有者の判断で、当面は全ての段を、向いた方向への半円の横切りで統一する。判定の扇は180度、距離は1.4である。全ての段が同じ動きなので、動きの型は`Swing`だけにした。
- 剣は体の右から前を通って左へ、攻撃方向を中心に-90、-30、30、90度の順に振る。横向きの試作は振り下ろしに近く、他の向きと回る向きが逆だったので描き直した。
- 背を向けた向きの攻撃では、剣と残像は体の向こう側に描く。
- 所有者の確認で、止まって振ると棒立ちに見えると分かった。止まって振るときだけ踏み込みの脚を見せ、上半身を脚のコマごとの兜の位置へ付ける。上半身の絵は走りながらと共用する。動きの絵なので、脚は武器の動きの型ごとに持つ。
- 踏み込みは見た目だけで、キャラクターの位置と判定は動かさない。
- 硬直は0.2秒あり持続より長いので、踏み込みの脚は硬直の前半まで最も深いコマで止め、後半で戻りのコマにする。
- 走りの脚の絵は、正面、横、背面で足が体の絵より7〜12 pixel高かった。走りながら振ると足が浮いて脚が上半身に隠れていたので、ツールが足元を体のコマへ揃える。
- 段のつながりはActionが次の段を持つ形にする。動きの型と同じく、武器の差はデータで出す。
- 振っている間に押した分は次の段へ予約する。硬直が終わった後も短い間だけ続けられ、過ぎると一段目へ戻る。
- 片手剣の値は仮である。一段目と二段目は今の値のまま、三段目は威力と範囲を上げて硬直を長くした。
- 所有者の判断で、まず騎士だけで動きを調整する。革装備は三段の絵がないのでSceneから外し、確認のTestも止めている。動きが固まったら絵を作り、外した箇所を戻す。
- 手首を軸に回す処理はやめた。剣はコマごとに測った手の位置と角度で動く。
- 振った剣は盾の手前に描く。元の絵のとおりで、同じ順だと盾に隠れるコマがあった。
- 斬撃は判定の扇の外周だと体から離れて見えたので、胸の高さで判定の7割の大きさにした。見た目より判定が広いままなので、剣の長さと判定の距離は遊びながら決める。

- 所有者の確認で、止まって斜めに振れないと指摘された（2026-11-08）。斜めの2つのキーは同時には離れず、`CharacterActor2D.Facing`が先に隣の向きへ変わっていた。表示だけが0.08秒待って斜めの立ち姿を保っていたので、斜めを向いて立っても攻撃は隣の向きになった。この待つ決まりを`CharacterActor2D`へ移し、表示と攻撃が同じ向きを使うようにした。

## 検証

Unity Editorが開いている間は、[テスト手順](../../development/testing.md)の一時複製で確認する。

- 一時複製でEditMode 313 / 313成功、PlayMode 33件中28件成功、5件失敗。失敗の5件は従来と同じStudyAのSetUp失敗である。
- 走りながら三段が続くこと、振る間も脚のコマが進むこと、振る間に盾が上半身に対して動かないこと、止まって振ると東、西、南で上半身が前へ乗り出すことは、森のSceneのPlayMode Testで確認した。
- 一時複製の実画面で、走りながらと止まっての振りを8方向すべて撮影して確認した。止まって振るときの踏み込みと腰の継ぎ目、走りながら足が地面に付くことも拡大して確認した。
- ツールの検査で、全方向の刃は半円から30度以内、盾の動きは5.3 pixel以内である。
- 本体のEditorでの見え方は未確認である。
