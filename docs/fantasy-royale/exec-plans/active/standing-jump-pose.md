# 止まって跳ぶときの跳躍のポーズ

## 目的

止まって跳ぶとき、立ち姿のまま浮くのをやめ、跳躍のポーズを見せる。

完了条件は次のとおり。

- 止まって跳ぶと、踏み切りと着地でしゃがんだポーズ、空中で脚をたたんだポーズを見せる。
- 5つの向きと、騎士、革の胴、布巻きサンダル、鉄の重靴のどの組み合わせでも崩れない。
- 剣、盾、弓は空中のポーズでも拳に付く。
- 走りながらの跳躍、空中での攻撃、影、着地の砂ぼこりは今までどおり動く。

## 背景と根拠

今は跳ぶと、立ち姿の絵をそのまま持ち上げる。走りながら跳ぶと、走りのコマがその場で止まる。所有者は2026-11-17に、少なくとも止まって跳ぶときの跳躍の動きが要ると判断した。走りの両足が浮くコマを空中で使う案（描き足しなし）と、跳躍のポーズを描く案を試しのGIFで見比べ、所有者は描く案を選んだ。走りのコマを使う案は、その場の跳躍が走り幅跳びに見える。

## 対象範囲

- 騎士の跳躍のシート（剣と盾を持った絵、持ち物のない絵、胴、足）と斜めのシート
- 革の胴、布巻きサンダル、鉄の重靴の跳躍のシート
- `Tools/MapAuthoring/build_hero_frames.py`の跳躍のコマの書き出し
- Scene Builderと`CharacterSpriteView`の跳躍のコマ
- `CharacterSpriteAnimator2D`の止まって跳ぶときの見せ方

## 対象外

- 走りながらの跳躍の絵。今は走りのコマが止まったまま浮く。揃えるかは、止まった跳躍を見てから所有者が決める
- 空中での攻撃の絵
- 跳ぶ高さ、時間、当たり判定

## 実装計画

1. ポーズは向きごとに2つにする。踏み切りと着地のしゃがみと、空中で膝を曲げて足をたたんだポーズである。シートは立ち姿と同じ並び（正面、横、背面の1枚と、斜め前、斜め後ろの1枚）で、上の行をしゃがみ、下の行を空中とする。
2. 剣と盾を持った騎士の跳躍のシートを、立ち姿のシートを見本に1枚試作する。
3. **Decision Gate:** 試作の見え方を所有者に見せ、残りの生成へ進むか決める。
4. 残りのシートを立ち姿と同じ順に編集で作る。剣と盾を持った絵（斜め）、持ち物のない絵、革の全身、胴と足、サンダルと重靴の順である。
5. ツールで跳躍のコマを書き出し、Scene Builderで定義へ入れ、`CharacterSpriteAnimator2D`が止まって跳ぶ間に見せる。
6. 本体のEditorでTestと撮影で確かめ、Documentationを更新する。

## 判断記録

- 2026-11-17: 所有者が跳躍のポーズを描く案を選んだ。範囲は止まって跳ぶときだけとし、走りながらの跳躍は後で決める。
- ポーズを2つにするのは、跳躍が0.42秒と短く、しゃがみと空中の2つで踏み切り、浮き、着地を表せるためである。立ち姿と同じく武器種で共通の胴にし、武器は拳の位置へ付ける。
- 試作は、剣と盾を持った立ち姿のシート`hero-idle-01.png`を見本に、`gpt-image-2.5-sunburst`の編集で2行3列のシートとして描かせた（1回、約0.025ドル）。上の行は膝を深く曲げたしゃがみ、下の行は膝を上げて足をたたみ、腕を少し横へ上げた空中のポーズになり、剣と盾は立ち姿と同じ手と側に残った。地図の大きさに縮め、立ち姿、しゃがみ、空中、しゃがみ、立ち姿と並べたGIFで所有者に見せた。
- 2026-11-17: 所有者が試作のまま残りへ進むことを承認した。試作を`hero-jump-01.png`として採用した。
- 斜めのシートは、斜めの立ち姿を1枚目、正面、横、背面の跳躍を2枚目の参照画像にし、ポーズは2枚目に揃えさせた。空中の斜め前は顔がやや正面寄りになったが、地図の大きさでは差が目立たないので採用した。
- 胴と足は、立ち姿のときのように騎士と革を1枚に並べて作らず、シートごとに編集した。跳躍のシートは2行あり、並べると4行になって絵が小さくなるためである。重ねて比べると、どのシートも元の体と位置が揃った。生成は試作を含めて16回、約0.42ドルだった。
- 縮尺は、兜の幅が立ち姿と揃う0.151にした。兜の幅は立ち姿のシートで約207 pixel、跳躍のシートで約185 pixelである。しゃがみは地図で約52 pixel、空中は約57 pixelの高さになり、立ち姿の約72 pixelより低い。
- 表示は止まって跳ぶときだけにした。跳躍の割合が0.12未満の間（踏み切りの約50ミリ秒）と着地から0.1秒はしゃがみ、その間は空中のポーズである。着地を`ApplyLift`で数えると、着地のFrameに立ち姿が1Frame挟まるので、`Refresh`の初めで数える。走りの間は着地のしゃがみを消し、止まった後に古いしゃがみが出ないようにする。
- 2026-11-17: 所有者が、身をかがめ過ぎかもしれないと指摘した。描いたしゃがみは地図で立ち姿の約72 pixelから約52 pixelまで縮む。実際の速さのGIFで、今、立ち姿の上半身を3 pixel沈める案、しゃがみをやめて着地で2 pixel沈むだけの案を見せ、所有者は3 pixel沈める案を選んだ。踏み切りと着地は立ち姿の足のまま胴、頭、持ち物を沈め、空中のポーズだけ描いた絵を使う。しゃがみの絵はシートと定義に残し、使わない。沈めるのは3層の体なら跳躍のコマを持たない部位でも同じである。
- 2026-11-17: 所有者が、首をすくめるのはもう少し弱めでよいと指摘した。空中のポーズでは、胴の上端から頭までの高さが立ち姿より2.8〜5.0 pixel低く、描いた肩が兜の周りへ上がっていた。ツールが空中のポーズの頭を、その差の半分を整数に丸めた分だけ上げる（正面、背面、斜め前、斜め後ろは2 pixel、横は1 pixel）。描き直しはしない。

## 検証

- 部位ごとのシートを、元の体のシートと半透明に重ねて、位置と姿勢が揃うことを確かめた。
- ツールの出力で、騎士、革の胴、布巻きサンダル、鉄の重靴の組み合わせの立ち姿、しゃがみ、空中を5方向並べて確かめた。既存のコマの出力は変わっていない（頭の位置の出力が前と一致）。
- Scene Builderで定義を作り直し、`HeroSprites.asset`と革、サンダル、重靴の定義に跳躍のコマが入ったことを確かめた。
- 本体のEditorでEditMode 374 / 374成功、森のPlayMode 41 / 41成功。追加した`ForestMap_StandingJumpCrouchesAndTucksTheLegs`は、空中で胴と足が同じ跳躍のコマになり、剣が拳に付いたままで、着地でしゃがんでから立ち姿へ戻ることを確かめる。
- Playで時間を遅くして跳び、正面、斜め後ろ、横、斜め前の空中のポーズを撮影した。剣と盾が拳に付き、影は地面に残った。
- 空中のポーズの頭を上げた後、Scene Builderで定義を作り直し、森のPlayMode 41 / 41成功。立ち姿、上げる前、上げた後の空中を並べた絵で確かめた。
- しゃがみを3 pixel沈めるだけに変えた後、森のPlayMode 41 / 41成功。Testを`ForestMap_StandingJumpSinksAndTucksTheLegs`へ改め、踏み切りと着地で立ち姿の足のまま胴が3 pixel沈み、空中ではしゃがみの絵を使わず、元の高さへ戻ることを確かめる。

## 完了結果

止まって跳ぶとき、踏み切りと着地で胴を3 pixel沈め、空中では足をたたんだポーズを見せるようにした。所有者のEditorでの確認がまだである。走りながらの跳躍を跳躍のポーズに揃えるかは未決定である。
