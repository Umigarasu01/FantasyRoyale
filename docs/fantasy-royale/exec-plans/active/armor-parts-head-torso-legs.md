# 防具の足、胴、頭への分割

## 目的

防具を足、胴、頭の3部位に分けて作り、部位ごとに着替えられるようにする。同じシリーズの3部位を揃えると、今の全身セットと同じ見た目になる。

完了条件は次のとおり。

- 騎士と革装備の頭と胴、足を、森の確認用Sceneで部位ごとに組み合わせられる。
- シリーズ外の部位を足しても破綻しない決まりが、[防具の部位デザイン規約](../../product-specs/art/armor-part-design.md)にある。
- 立ち姿、走り、走りながらの攻撃、止まっての攻撃の全てで、どの組み合わせでも継ぎ目と重なり順が崩れない。
- 武器はどの組み合わせでも今までどおり持てる。
- 部位の絵が足りない組み合わせは、Scene BuilderとEditMode Testで止まる。

## 背景と根拠

所有者は、武器種ごとに共通の動きを使い、あらゆる防具と武器を組み合わせられるようにする要件を整理し、足、胴、頭の分け方の検討を求めた。検討の結果を受けて、分ける形で作ると決めた（2026-11-07）。要件と検討の結果は[装備と動きの要件](../../product-specs/equipment-and-motion.md)にある。

検討で分かったことは次のとおり。

- 全身セットは同じ体の着替えなので、輪郭がずれない。
- 向きごとに1枚の頭を走りの全コマへ載せても崩れない。
- 頭と胴の継ぎ目は、騎士と革装備の試作4枚で確かめた。結果は判断記録にある。

## 対象範囲

- 頭、胴、足の絵の作り方と、`Tools/MapAuthoring/build_hero_frames.py`の切り出し
- `CharacterSpriteAnimator2D`の3層の表示
- `CharacterSpriteSetDefinition`の部位の持ち方と、組み合わせの検査
- 騎士と革装備の絵
- 森の確認用Sceneの部位ごとの着替え

## 対象外

- 防具の性能、価格、入手方法。部位ごとに売るかも未確定である
- ローブのように腰をまたぐ全身専用の防具
- 手袋の色が違う胴の拳の色変換
- 弓を引く動きの絵
- 二段目と三段目の動きの違い

## 実装計画

1. 頭と胴を4枚だけ試作し、継ぎ目と重なり順を実際の絵で確かめる。
2. シリーズ外の部位を作って組み合わせ、破綻しない設計を固める。
3. **Decision Gate:** 残りの絵の生成の承認を得る。
4. 騎士の絵を部位へ切り替え、3層で表示する。見た目が今と変わらないことを確かめる。
5. 革装備の絵を作り、組み合わせの検査を足す。
6. 森の確認用Sceneで部位ごとに着替えられるようにする。
7. Testと実画面で確認し、Documentationを更新する。

## 判断記録

- 所有者の判断で、一旦部位ごとに分ける方向で進める。シリーズ外の部位でも破綻しない設計を固める。枠ごとの性能は未確定である。
- 腰当ては胴に含める。足は靴と脚甲だけになり、腰から腿の上部は共通の暗いズボンとする。止まって振る脚や走りの脚と胴の腰当ては別々に動くが、今の絵で仮に重ねた範囲では目立たなかった。
- 全ての部位を、頭、胴、足を離して並べた基準の絵から描く。シリーズ外の部位も形が揃い、組み合わせで破綻しなかった。
- 革の足は騎士の足と同じ絵になったので、今回は作らない。足の枠としては同じ物である。
- 所有者の確認で、三角帽子だけ首が短く見えると分かった。生成で顔が4 pixel下がっていた。頭はあごの高さで揃える。
- 部位ごとの定義Assetの型は増やさない。`CharacterSpriteSetDefinition`は頭、胴、足のうち持つ部位だけを持ち、`CharacterSpriteAnimator2D.SetArmour`が部位ごとに別の定義を着せる。騎士は3部位、革は頭と胴、素顔は頭だけである。敵は足のコマを持たないので、今までどおり体全体の絵を1枚で見せる。
- 手の位置と兜の位置は胴の定義が持つ。全ての定義が騎士の値を共有するので、足と頭を別の定義にしても位置は変わらない。
- 体全体の絵は表示しない。手、兜、剣の角度を測るために残す。部位のコマはツールが体全体のコマへ合わせる。足はシートの丈が違うことがあるので、足元を揃える。
- 重ねる順は足、胴、頭とする。革のフードのように胴へ被さる頭があるためである。
- 所有者の依頼で、全装備を確認用の画面で自由に切り替えられるようにした。部位を順に替えるショップのボタンは、この画面へ置き換えた。
- 装備は個別に登録しない。防具はシートの名前の`<id>`から、Folder、定義Asset、一覧までつながる。武器は定義Assetの`Id`で一覧へ載る。`Assets/Resources`へ移す案は全ての絵を常に読み込むので採らず、Editorが定義Assetを集めた`CharacterEquipmentCatalog`をSceneが参照する。
- 定義Assetの保存先を`Characters/Sets/<id>.asset`へ揃えた。`HeroLeatherSprites`と`HeroBareHeadSprites`はGUIDを保ったまま移した。
- 所有者の指摘で、確認用の画面を分類ごとの一覧にした。数が増えても選べるように、武器、頭、胴、足を切り替え、武器は武器種でも絞る。武器種は通常攻撃の動きの型から決まるので、武器ごとの登録は増えない。
- 所有者の依頼で足の部位を足した。検討で組み合わせを確かめた布巻きとサンダル、鉄の重靴を本番の足にした。騎士の足のシートを参照にして膝から下だけを描き替えると、同じ姿勢と位置のまま描けた。1種類につき6枚である。
- 足は細く、靴の形が変わると輪郭の多くが変わるので、ツールが止める重なりの下限は胴の70%より低い60%とした。実際は2種類とも92%以上だった。止まって振るときの足は騎士の足元へ揃え、騎士より腰が下がれば止める。
- 買った武器と確認用の武器は分ける。`equipment`は買って増える武器の順で、一覧とは別に残す。
- 左クリックは攻撃にも割り当てられているので、確認用の画面を押したクリックでは攻撃しない。Jは画面の上にマウスがあっても効く。ショップの画面は今までどおりで、押すと振る。
- 頭は5方向を1枚の参照へ並べると、1回の編集で作れた。全身セット1着分のシートは13枚のままである。
- 胴の生成は体のシートと位置が少しずれる。手の位置は体のコマから測った値を使うので、ツールが胴を体のコマへ合わせる。
- 今の脚のシートは太ももが体の絵より長い。全体を縮めると歩幅も縮んだので、高さだけを合わせる。
- 試作では、胴が体の絵より数pixel高い位置に合い、騎士のスカーフが頭に隠れた。背面の頭には元の絵にない髪が描かれた。胴の合わせ方と、騎士の頭の描き直しで直す。

## 検証

- 騎士と革装備の頭と胴を試作し、走りの正面、横、背面で頭と胴の全組み合わせを重ねた。頭と胴の継ぎ目は崩れなかった。
- シリーズ外の6部位を含む頭4種、胴4種、足3種の全48通りを、立ち姿の正面で重ねた。結果と対策は[防具の部位デザイン規約](../../product-specs/art/armor-part-design.md)にある。
- 一時複製でEditMode 313 / 313成功、PlayMode 33件中28件成功、5件失敗。失敗の5件は従来と同じStudyAのSetUp失敗である。
- 3層で表示すること、部位を替えるとその絵だけが替わり、武器と手の位置が残ることは、森のSceneのPlayMode Testで確認した。
- 一時複製の実画面で、騎士の立ち姿、走り、走りながらの振り、止まっての振りを8方向で撮影して確認した。頭3種と胴2種の組み合わせを、正面、斜め前、横、斜め後ろ、背面で撮影して確認した。
- idで引く全装備の一覧を入れた後、一時複製でEditMode 317 / 317成功、PlayMode 34件中29件成功、5件失敗。失敗の5件は従来と同じStudyAのSetUp失敗である。一覧には素顔、騎士、革と弓、剣が載り、スライムは載らないことを確認した。
- 確認用の画面は画面付きのEditorで撮影し、分類の切り替え、武器種での絞り込み、身につけている物の印を確認した。部位を組み合わせた待機、走り、振りも撮影し、剣と弓で重なりが崩れないことを確認した。
- 足の部位を足した後、一時複製でEditMode 317 / 317成功、PlayMode 34件中29件成功、5件失敗。失敗の5件は従来と同じStudyAのSetUp失敗である。足の2種類を頭と胴の組み合わせへ重ね、待機、走り、止まっての振りを5方向で撮影して確認した。
- 本体のEditorでの見え方は未確認である。
