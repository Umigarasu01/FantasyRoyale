# 森マップをゲームとして整える

## 目的

森マップの設置物を、草地に馴染む絵で必要なものだけ新しく描き直し、敵と宝箱を置いて、遊びながらマップを調整できる状態にする。

完了条件は次のとおり。

- 必要な設置物が同じ描き方の新しい絵になり、地図生成に組み込まれている。
- 森の確認用Sceneで攻撃、雑魚敵、宝箱、倒れたときの復帰を試せる。
- 物の大きさと配置に理由があり、マップ端に見えない壁が残っていない。

## 背景と根拠

2026-11-06の点検で、今の絵は草地だけが細かい粒で描かれ、建物や木はコントラストの強いきれいな絵で、騎士はさらに細かいと分かった。所有者は設置物を仮のものと位置付け、必要なものを新しく描く方針を決めた。

見た目の基準は[Map Plan](../../product-specs/art/map-plan.md)の草地である。

## 対象範囲

- 設置物の一覧、絵の生成、地図生成への組み込み
- 物の大きさ、配置、マップ端
- 森の確認用Sceneへの攻撃、雑魚敵、宝箱、復帰の追加

## 対象外

- 地形の変更（道、川、森の形は承認済み）
- 騎士の絵の描き直し（仮のまま）
- 商人の売買、育成の数値、最終バトル
- 地面の絵の変更

## 実装計画

1. 新しい絵の基準を決める。草地と所有者が認めた描き直し見本を参照に、木と村の物を描いて地図の上で確かめる。
2. 残りの設置物を描き、地図生成へ組み込む。大きさと判定は設置物の一覧で持つ。
3. 配置を直し、マップ端をふさぐ。
4. 森のSceneへ攻撃を持ち込む。
5. 雑魚敵を1種類、固定の場所に置く。
6. 宝箱と、倒れたときの復帰を入れる。
7. 遊びながら数と配置を調整し、固定の置き場所をランダムの候補へ広げる。

## 判断記録

- ゲーム画面の解像度は下げない。640×360と480×270を試作したが、所有者の判断で採用しない。粗さの差は解像度ではなくデザインの問題として扱う。
- 既存の絵の加工では描き方まで変えられないため、新しく描く。
- 仮のルールとして、敵は近づくと追いかけて触れるとダメージを与え、倒すとコインが増える。宝箱からは弓が手に入り、開始時は剣だけとする。倒れたら村に戻ってHPが全回復する。
- 点検では、岩と柵の判定に問題はなかった。直すのはマップ端で、川沿いの岸が南北の端まで歩ける。
- 川の南北の端は森を水際まで寄せて閉じた。歩ける範囲はマップ端の1 Unity単位より内側に収まる。
- 設置物は`forest_objects.py`の34種類へ置き換えた。旧Libraryと施設の原画は地図生成から外した。
- 復帰のために`CharacterHealth.Revive`を追加した。通常回復とは別の明示的な効果という既存の方針に沿う。
- 敵は一直線に追うだけで、木や岩を回り込まない。経路探索は遊んでから判断する。
- 噴水と泉の回復は既存の回復の泉のEventを使う。ランダム配置は既存のEvent抽選を敵と宝箱へ流用した。ランダムの範囲はProduct Decisionが未確定なので、敵と宝箱だけとし、施設は固定のままとする。
- 所有者の依頼で、ショップと装備の見た目の反映を入れた。売り物は回復薬と弓で、弓はショップで買う形に変えたので、宝箱の中身はコインだけにした。
- 装備の見た目は、素手の体のアニメーション1組へ部品を重ねる形にした。最初に作った装備ごとの絵一式は、装備を増やすたびに走りを全部描くことになるので取りやめた。
- 武器の全姿勢差分は手で描かず、絵1枚とツールの回転、体が持つ手の角度で作る。武器の数と姿勢の数の掛け算を足し算にするためである。剣で試作し、線の荒れは見られなかった。弓と盾は未適用である。
- 所有者の要求は、装備が増えてもアニメーションを保ったまま差し替えやすいことである。手の位置はコマごとに`anchors.json`へ持ち、部品の不足はScene BuilderとEditMode Testで止める。
