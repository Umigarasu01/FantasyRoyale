# 店の画面

## 目的

[UIのデザイン方針](../../product-specs/art/ui-design.md#店の画面)で決めた「店の広い枠」の店の画面を、森の確認用Sceneで開けるようにする。店主の顔、商品一覧、商品説明、自分の持ち物の4つを出す。

完了条件は次のとおり。

- 中心街のお店の前でEを押すと、黒漆の店の画面が開く。店ごとに店主の顔と名前と台詞が替わる。
- 商品の行の一覧から選ぶと、右に大きな絵、名前、説明、強さ、値段が出る。今の物との差が緑の数字で出る。
- 買うと、コインが減り、持ち物の枠と商品の状態（装備中、持っている）が変わる。
- 右の枠に、着ている頭、胴、足、持っている武器と、袋の枠が出る。
- 確認用のOnGUIのショップは外す。

## 背景と根拠

2026-11-10に、所有者は店の画面に4つの要素を求め、並べ方を「店の広い枠」に決めた。決まっていない部分は仮置きでよいとした。

今のショップは`ForestMapPreviewDebug`のOnGUIで、回復薬（5コイン、HP 30回復）と弓（20コイン）の2つのボタンだけがある。どの店でも同じ物が開く。防具は確認用の全装備の画面で代金なしに着替えられるだけで、買えない。持ち物の仕組みはない。

## 対象範囲

- HUDのAssemblyに店の画面`ShopScreen`と、表示する値の型を足す
- 店主の顔と品物のアイコンの仮の絵を作るツール
- 選んだ行の金の囲みと矢印の絵
- 森の確認用Sceneの仮の品揃え、買う処理、店にいる間の操作
- Test、文書

## 対象外

- 正式な品揃え、値段、レア度、在庫の共有
- 正式なアイコンの絵、店主の顔の絵
- 持ち物の仕組み（袋の枠の数、売る、拾う、捨てる）
- 防具の強さ（今の防具は見た目だけ）

## 仮置きの決め（2026-11-10、所有者が仮置きでよいとした）

| 項目 | 仮の決め |
| --- | --- |
| 品揃え | 全ての店で同じ。回復薬、剣、弓、全装備の一覧にある防具の部位（素顔を除く） |
| 値段 | 回復薬5、弓20（今のまま）、剣10、防具は部位ごとに6〜20 |
| レア度 | 回復薬、剣、革、布巻きサンダルは白、弓と鉄の重靴は青、騎士は紫 |
| 店主 | 店の絵の窓や台の向こうの店主を切り出して拡大する。名前は店の種類（武器屋など）、台詞は店ごとに1行 |
| アイコン | ゲームの絵から切り出す。防具は正面の部位の絵、武器は手に持つ部品の絵、回復薬は屋台の赤い瓶 |
| 店にいる間 | ゲームは止めない。騎士は動かず、攻撃しない。倒れると閉じる |
| 操作 | W、Sか上下で選ぶ。Jで買う。Eで閉じる。2026-11-11からはマウスでも選び、買い、閉じられる |
| 買った物 | 武器と防具は買うとその場で持ち替え、着替える。持っている物を選んでJを押すと、代金なしで持ち替え、着替える。回復薬はその場で飲む |
| 袋 | 持っているが手や体に着けていない武器と防具を入れて見せる。8枠 |

## 実装計画

1. 絵: `build_hud_sprites.py`に選んだ行の金の囲みと矢印を足す。新しい`build_shop_art.py`で、店主の顔とアイコンをゲームの絵から切り出し、整数倍に拡大して書き出す。
2. HUD: `HudSkin`に本文のフォントと囲みと矢印を足す。`HudIconLibrary`で名前から絵を引く。`ShopScreen`が店の画面を組み、`GameHud`がピクセルフォントの大きさをまとめて合わせる。
3. 確認用Scene: 仮の品揃えを作り、店を開く、選ぶ、買う、閉じるを`ShopScreen`へ渡す。OnGUIのショップを外す。
4. Test: 店の画面の開閉、選ぶ、買う、持ち物の変化をPlayModeで確かめる。
5. 1080pの画面で撮って確かめ、文書を更新する。

## 判断記録

- 2026-11-10: 仮のアイコンと店主の顔は、画像生成でなくゲームの絵から切り出す。品揃えも絵もまだ決まっていないので、作り直しになる物に費用をかけない。ドット絵は整数倍に拡大し、店主の顔はPoint filterで取り込む。
- 2026-11-10: 胴の部位の絵は横幅が49 pixelあり、96 pixelの枠に2倍で入らない。アイコンの枠を128 pixelにし、収まる最大の整数倍で拡大した。アイコンは一覧、説明、持ち物で大きさが違うので、Bilinearで取り込み、縮めたときは滑らかにする。
- 2026-11-10: 剣の絵は刃と鍔の部品と柄頭の部品に分かれ、握りは拳に隠れて描かれていない。仮のアイコンは刃と鍔の部品だけにした。
- 2026-11-10: 確認用Sceneは`ForestMapPreviewDebug`を分割し、店の処理を`ForestMapPreviewDebug.Shop.cs`に置いた。1つのファイルが1100行を超えていたため。
- 2026-11-10: `GameHud`のピクセルフォントの大きさ合わせを、登録した全ての文字に効くようにした（`RegisterPixelText`）。店の画面の文字も、画面の高さが変わったら元の格子の整数倍へ合わせ直す。
- 2026-11-10: 後ろを暗くする黒は不透明度0.75にした。0.55では線形の色空間のため、後ろが3割ほどしか暗くならなかった。
- 2026-11-10: 店にいる間の買うキーは、攻撃のActionをキーボードで押したときだけにした。攻撃のActionはマウスの左クリックにも割り当ててあり、クリックで買ってしまうため。
- 2026-11-10: 買った知らせは緑、買えなかった理由は赤にした。
- 2026-11-11: 所有者がマウスも使えるようにとし、カーソルを金の矢印に決めた。カーソルはOSのハードウェアカーソルでなく、HUDのCanvasに置く絵にした。画面の高さに合わせて大きさが揃い、ピクセルフォントと同じく1920×1080を基準に描けるため。当たりはEventSystemを使わず、`ShopScreen.HitTest`が`RectTransformUtility`で調べる。確認用Sceneに今EventSystemがなく、店の画面の他にマウスで押すuGUIがないため。
- 2026-11-11: マウスは動かしたときだけ行を選ぶ。止まったマウスが毎フレーム行を選ぶと、キーボードで選んだ品物を取り返してしまうため。
- 2026-11-11: 乗ったキーは最初は金に光らせたが、金のカーソルと同じ色で見分けにくかった。キーは白のまま1.12倍にし、横の言葉だけを金にした。
- 2026-11-11: PlayMode Testは、本物のマウスの位置で結果が変わらないよう、`LoadForest`で`SetMouseIgnoredForTests(true)`にする。

## 検証

- 所有者の開いているEditorでUnity MCPから実行した。EditMode 337 / 337成功。PlayModeの`ForestMapPreviewPlayModeTests` 27 / 27成功（`ForestMap_ShopScreenShowsKeeperGoodsAndInventory`を含む。店主、一覧、持ち物、店にいる間に動かないこと、買えないときの知らせ、弓を買って剣が袋へ入ること、革の頭を買って騎士の頭が袋へ入ること、店ごとの店主を確かめる）。他のPlayMode Testは実行していない。
- 武器屋と防具屋で開いた画面を1920×1080で撮った（[ゲームの画面](../../product-specs/art/ui-samples/shop-in-game.png)）。Screen Space OverlayのCanvasは撮れないので、撮るときだけScreen Space Cameraへ替えた。
- 実際のキー入力（W、S、J、E）での操作は、Editorで手で確かめていない。Testは品物を選ぶ、買う、閉じるの処理を直接呼んでいる。

## 完了結果

- 森の確認用Sceneのお店の前でEを押すと、店主の顔、商品の一覧、説明、持ち物の店の画面が開く。OnGUIのショップは外した。
- 足した物: `ShopScreen`、`ShopScreenModel`ほかの値の型、`HudIconLibrary`、`HudLayout`（`FantasyRoyale.Gameplay.Hud`）、`ForestMapPreviewDebug.Shop.cs`、`Tools/UiAuthoring/build_shop_art.py`、選んだ行の金の枠と矢印と無地のキーの絵。
- 2026-11-11: マウスでも店を使えるようにし、金の矢印のカーソルを足した。EditMode 337 / 337、森のPlayMode 29 / 29成功（`ForestMap_ShopScreenWorksWithTheMouse`を含む）。
- 残る事項: 正式な品揃え、値段、レア度、在庫の共有、店主の顔とアイコンの正式な絵、持ち物の仕組み、店にいる間にゲームを止めるか、防具の強さ。本物のマウスとキーでの操作は、Editorで手で確かめていない。
